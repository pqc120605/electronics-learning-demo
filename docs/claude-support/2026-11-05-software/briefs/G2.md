## Thiết kế đề xuất

### Lát 1 (L) · Compile service

```
Trình duyệt ──POST /compile {fqbn, sketch, libs[]}──▶ API (giới hạn tốc độ, xác thực lớp học)
                                                        │
                                                        ▼
                                           Hàng đợi ─▶ Worker container (arduino-cli, core cài sẵn)
                                                        │   no network, read-only rootfs,
                                                        │   CPU 1, RAM 512 MB, timeout 60 s
                                                        ▼
◀── {status, log, artifact: base64, sha256, fqbn, coreVersion, cliVersion} ──
```

Hợp đồng phía web (repo sản phẩm chỉ có client):

```ts
// src/lib/compileClient.ts (mới)
export type CompileRequest = {
  fqbn: 'arduino:avr:uno' | string          // whitelist phía server
  sketch: string                              // tối đa 64 KB
}
export type CompileResult =
  | { ok: true; format: 'hex' | 'uf2' | 'bin'; artifact: Uint8Array; sha256: string; fqbn: string; coreVersion: string; cliVersion: string; log: string }
  | { ok: false; reason: 'compile-error' | 'timeout' | 'rate-limited' | 'unsupported-board' | 'service-unavailable' | 'auth-required'; log: string }
// accessToken lấy từ supabase.auth.getSession(); không có session thì trả 'auth-required' trước khi gọi mạng
export async function compileSketch(req: CompileRequest, accessToken: string | null, signal: AbortSignal): Promise<CompileResult>
```

- Server chỉ nhận FQBN trong whitelist (Uno, Pico, ESP32 DevKit) và **không** cho thư viện tùy ý ở MVP; chỉ thư viện cài sẵn trong image.
- Mỗi kết quả gắn `sha256`, `fqbn`, version core và CLI; HEX Uno đi thẳng vào AVR8js (cùng đường với W2), UF2 Pico đi vào rp2040js (G1), `.bin` ESP32 đi vào lát 2.
- Code server **không** thuộc repo `electronics-learning-demo` [box01 chọn repo/thư mục; ngoài phạm vi brief này].

### Vận hành (quyết định founder 06/11/2026)

**Giai đoạn pilot: Raspberry Pi 5 tại chỗ.** Raspberry Pi 5 8 GB, SSD, tản nhiệt chủ động, Linux 64-bit, Docker; chạy **1 lượt compile mỗi lần**, phần còn lại xếp hàng. Ra Internet qua Cloudflare Tunnel hoặc Tailscale Funnel, không mở port router. Máy chỉ dùng cho service, đặt ở mạng khách/VLAN riêng nếu router hỗ trợ.

**Lát 0 (S, bắt buộc trước khi mua máy) · Kiểm toolchain ARM64 (box02):**
1. arduino-cli có bản phát hành Linux ARM64 ở version định ghim.
2. Mỗi core trong whitelist (`arduino:avr`, core RP2040 box02 chọn ở G1, core ESP32 cho `esp32-devkit`) có toolchain cho `aarch64`/Linux ARM64 trong package index. Ghi version core, tên gói tool, URL tải.
3. Nếu một core thiếu toolchain ARM64: board đó không compile trên Pi; ghi rõ và để board đó dùng firmware mẫu hoặc chờ VPS x86_64.
Đầu ra: bảng 3 dòng (core, version, có/không ARM64, nguồn). Không mua phần cứng khi bảng chưa xong.

**Lát 0b (S, sau khi có máy, người làm):** đo thời gian compile lần đầu và lần sau (có cache) cho 3 sketch mẫu, RAM đỉnh, nhiệt độ CPU. Tiêu chí pilot: Uno ≤ 30 s, Pico ≤ 60 s, ESP32 ≤ 120 s ở lần có cache; RAM đỉnh < 80 %; không throttle nhiệt [ngưỡng đề xuất, founder/box08 duyệt].

**Giai đoạn mở rộng: VPS.** Chuyển cùng image Docker (build đa kiến trúc `linux/arm64` + `linux/amd64`) lên VPS khi chạm điều kiện trong `../founder-decisions.md`. Cấu hình VPS khởi điểm (giả định, phải đo lại): 1 VPS Linux, 2 vCPU, 4 GB RAM, 40 GB SSD; tối đa 2 lượt đồng thời. Chốt lại sau khi đo thời gian compile thật của 3 FQBN (Uno, Pico, ESP32) ở lát 1, theo công thức: `số lượt đồng thời cần = lượt compile/phút lúc cao điểm × thời gian compile trung bình (phút)`.

**Lớp bảo mật bắt buộc trước khi mở cho học viên:**

| Lớp | Yêu cầu |
|---|---|
| Mạng vào | Pilot (Pi): không mở port router; mọi truy cập qua tunnel; SSH chỉ trong mạng nội bộ hoặc qua Tailscale, đăng nhập bằng khóa. VPS: chỉ mở 443 và SSH bằng khóa; tường lửa chặn mọi cổng khác |
| API | Reverse proxy có TLS; **bắt buộc đăng nhập** (quyết định founder 06/11): mỗi request mang JWT Supabase, server kiểm chữ ký và hạn token trước khi xếp hàng; rate limit và hạn mức theo user ID; giới hạn body 64 KB. Không có JWT hợp lệ trả 401, không chạy compile |
| Tài khoản | Dùng lại Supabase Auth đã có (`src/lib/supabase.ts:8-15`). **Học viên tự đăng ký bằng email** (quyết định founder 06/11); bật xác nhận email trong cấu hình Supabase Auth [box05 kiểm tùy chọn trong docs Supabase hiện hành]. Server compile chỉ chấp nhận JWT của user đã xác nhận email (kiểm claim tương ứng [box05 xác nhận tên claim]); không lưu mật khẩu; chỉ lưu user ID, số lượt, thời điểm. Hạn mức theo user ID cộng hạn mức tổng theo IP ở reverse proxy để chống tạo nhiều email. Xác nhận tuổi/đồng ý phụ huynh trước khi mở đăng ký công khai [cần chuyên gia pháp lý] |
| Container compile | Mỗi lượt một container mới từ image cài sẵn arduino-cli + core; `--network none`, rootfs chỉ đọc, thư mục làm việc tạm (tmpfs), user không phải root, giới hạn CPU/RAM/PID, timeout 60 s, xóa sau lượt |
| Image | Ghim version arduino-cli và từng core; build image có ghi SHA-256; không cài thư viện theo yêu cầu học viên |
| Dữ liệu | Không lưu sketch sau khi trả kết quả, trừ log lỗi không chứa mã (chỉ mã lỗi, FQBN, thời gian) |
| Vận hành | Vá OS hằng tháng; cập nhật image theo lịch có test hồi quy (compile 3 sketch mẫu, so SHA-256 artifact với lần trước khi version không đổi); theo dõi CPU/RAM/hàng đợi; cảnh báo khi dịch vụ không phản hồi |

Lớp cô lập mạnh hơn container thường (gVisor, Firecracker) [chưa kiểm chứng; box08 đánh giá nếu cần].

**Test service bổ sung (repo service):** sketch thử mở socket, ghi ra ngoài thư mục làm việc, fork bomb và vòng lặp vô hạn ở bước tiền xử lý đều phải thất bại hoặc bị kill trong ≤ 60 s mà không ảnh hưởng lượt khác.

### Lát 2 (M) · Nạp ESP32 DevKit bằng esptool-js

```ts
// src/lib/webSerialFlash.ts (mới) · chỉ chạy khi người dùng bấm
export type FlashPlan = {
  boardId: 'esp32-devkit'
  images: Array<{ offset: number; bytes: Uint8Array; sha256: string }>  // bootloader/partitions/app theo output arduino-cli [box02 xác nhận offset]
}
export type FlashResult = { ok: true; chip: string } | { ok: false; reason: 'unsupported-browser' | 'user-cancelled' | 'hash-mismatch' | 'wrong-chip' | 'write-failed'; message: string }
export function canUseWebSerial(nav: Navigator): boolean
export async function verifySha256(bytes: Uint8Array, expected: string): Promise<boolean>
```

- Dùng `Transport` và `ESPLoader` của esptool-js 0.7.1 (README repo, mục "Create Transport and ESPLoader"); box05 đọc README đúng version, không đoán chữ ký hàm.
- Hai bước xác nhận: chọn cổng, rồi "Ghi firmware lên board" kèm tên chip đọc được. Sai chip thì dừng.
- Sau khi nạp: màn hình Serial Monitor qua Web Serial (chỉ đọc/ghi text, không REPL).

## Test cần viết

`node --test tests/compile-client.test.mjs` (fetch giả):
1. Kết quả `ok` có `sha256` không khớp bytes thì client trả `hash-mismatch`, không đưa artifact vào emulator.
2. HTTP 429 trả `rate-limited`; mạng lỗi trả `service-unavailable` kèm thông báo tiếng Việt và gợi ý xuất `.ino`.
3. `AbortSignal` hủy giữa chừng không để lại kết quả cũ (giống `createFirmwareLoadGuard`, `src/lib/firmwareWorkflow.ts:4`).
4. Sketch > 64 KB bị chặn trước khi gửi.
4a. `accessToken` null trả `auth-required` và **không** gọi `fetch`; HTTP 401 (gồm trường hợp email chưa xác nhận) cũng trả `auth-required`, UI nhắc "Xác nhận email để biên dịch" khi server báo lý do đó. UI hiện "Đăng nhập để biên dịch", các tính năng khác vẫn dùng được không cần tài khoản.

`node --test tests/web-serial-flash.test.mjs`:
5. `canUseWebSerial({} as Navigator)` trả `false`.
6. Transport giả trả chip khác ESP32 thì `wrong-chip`, không gọi ghi.
7. Đổi 1 byte image thì `verifySha256` trả `false`.

Service (repo riêng): test sandbox: sketch cố mở socket hoặc đọc file ngoài thư mục làm việc phải thất bại; sketch vòng lặp compile lâu bị timeout 60 s. Box08 review.

Bench (người, không phải agent): biên dịch blink cho ESP32 DevKit, nạp, thấy LED nháy; ghi chip ID, version core, log.
